From 308 articles to one causal graph

One command, ./run.sh corpus/ output/, turns the restoration articles in corpus/ into one merged CAMO v0.10.0 graph in YAML and JSON. A Qwen model on the shared endpoint does the reading; everything around it is deterministic code. Click a stage to read how it works.

Submitted configuration

The judges score annotation quality first, then energy per article (LLM tokens). Every number on these pages comes from our own scorer on eight reference papers; they are development numbers, not the judges' score.

Reference annotations

To measure anything we need answers to compare against. Only one exists from a human; the rest we made with Claude and then cleaned.

filepapermade byrole

How the Claude annotations were made and cleaned

Claude read each paper and wrote a CAMO graph in the style of the organisers' Murphy 2005 example. Because a model wrote them, they are treated as an out-of-sample check, never as truth. Cleaning (dev/annot_fix.py, every change listed in dev/annot_v2/CHANGES.md; originals untouched):

  1. Character offsets. 1,190 quoted spans located in the markdown so raw[start:end] is the span.
  2. Taxon IDs. Species written as names became NCBITaxon IDs where our table has them.
  3. Terms name the entity only. Method detail in brackets moved out of entity_term / measured_attribute.
  4. 38 hand edits reduced over-specified terms to the entity ("broadcast glyphosate application without species targeting" → "glyphosate application").
  5. Claim review. All 209 edges of the four first files read against their sentences: 4 edges quoted a sentence that did not support them (fixed), 4 null results that were only in the notes became edges, 11 claims reported from other studies were removed (the human Murphy annotation has none).

Effect: on ITXNQ843 the pipeline and the annotation stated nearly the same claims, yet loose F1 was 0.05 because every annotated subject carried method detail; after cleaning it was about 0.5.

Development and regression split

Murphy (human) is the primary yardstick and is always reported on its own. Three Claude papers are used while developing (dev3). Four are a fixed regression set (reg4): changes are not tuned on them, they only confirm or reject.

Stage 1 · Preprocessing

The model never sees the raw article. Stage 1 keeps the text where the authors state their own findings, numbers every sentence, and adds a species legend and a little context. Default: paragraph-chunks.

Paragraph selection (teammate's team_paper.py, used verbatim)

Cleaning
  • unicode normalisation, HTML, citation superscripts, image placeholders, markdown links
  • page artefacts, running headers, metadata lines (affiliations, received/accepted)
  • hyphenation fixed, split paragraphs rejoined, tables and fragments removed
  • inline citations "(Smith et al. 2010)", figure/table references and URLs removed
  • duplicate paragraphs removed (word-shingle overlap)
Routing by section
  • Abstract, Results, Discussion, Conclusion → extract
  • Methods, title, supplementary → context only
  • Introduction → dropped (aims sentences kept as context)
  • References, acknowledgements, funding, data → dropped
Selection by causal cues

Each paragraph is scored; a category counts at most twice.

cueweight
null result ("no significant", "did not affect")3 (always kept)
causal verb (increase, reduce, suppress, …)2
finding frame ("our results suggest")2
management / agency2
association, statistic2
comparison, hedge, mechanism1
methods-like wording−1
Paragraphs scoring ≥ 3 are kept; the abstract always.
Packing and numbering
  • Kept paragraphs are packed into chunks of ≤ 2,500 Qwen tokens; one model call per chunk.
  • Each sentence gets a global number and a section tag: [24] (res) …; its raw-markdown character offsets are kept for the source spans.
  • Every chunk repeats the header: TITLE, SPECIES legend, CONTEXT.

Header added to every chunk (our stage 1)

SPECIES legend: Latin binomials found in the paper, with abbreviations ("S. canadensis") and common names, as T-codes (T1=Sanguinaria canadensis (S. canadensis)). The model writes T-codes; code turns them back into names and NCBITaxon IDs, so the model never has to spell a Latin name or an ID.
CONTEXT: about 400 tokens from the Methods/Introduction (site, design, aims) — background only, the prompt says not to annotate it. Token counts use the Qwen tokenizer; a clean install without it uses a precomputed table of Qwen counts for this corpus, so chunks are identical.

Alternative stage-1 models kept for comparison: --preprocess sentence (our sentence-level filter with cited-background removal and statistics compression), paragraph, sentence-chunks. Open the paper explorer to see the kept text, the dropped paragraphs and their reasons for any reference paper.

Stage 2 · Ontology grounding

Rule: the LLM never writes an ontology ID. Code looks names up in local tables, and only an ID a person has checked is written.

Taxa → NCBITaxon

data/ncbitaxon_names.tsv: 1,938 names with NCBI Taxonomy IDs. Every legend species is looked up (exact name, then case-insensitive, then genus + epithet). A taxon node's entity_term becomes e.g. NCBITaxon:126270; the node name keeps the readable species name.

Taxon ID accuracy on Murphy matched pairs: 0.99.

Attributes and entities → PATO / ENVO / …

data/terms.tsv: 25 rows, 20 verified by hand (e.g. height → PATO:0000119). Only verified rows are ever emitted; everything else stays free text, which the schema allows.

Off by default and tested: --taxon-groups (group words such as "rodents" → Rodentia; mixed result). Not in the submission: an exact-label lookup in PATO/ELMO/ENVO/GO/ChEBI from the team's ontology module (built and validated, neutral on our scorer).

Stage 3a · The prompt

A compact line format instead of JSON: about four times fewer output tokens, and code (not the model) builds the CAMO objects. One line per claim: F = finding, N = null result.

Line anatomy 
F|12|T1/initial planting density/+/tax|c|T2/number of individuals/-;T2/height/-|D|exp|stage=seedling|dose=9-11 ramets/m2
 │  │  └ cause: thing/property/change/type   │ └ effects (; = separate outcomes)     │  │   └ optional keys
 │  └ sentence numbers                         └ predicate (c causes, p prevents, a associated…)  │  └ design (exp/obs/rev/mod/jud)
 └ F finding / N null                                                                    └ language D direct / U hedged / A associational

Stages 4–6 · Post-processing

  
Deterministic code turns the claim lines into schema-valid CAMO. Every change here was measured exactly by replaying the
  same saved model answers through old and new code.

  
4a · Parse (lenient where the meaning is unambiguous)

  
About one line in six from this model breaks the format. The old parser dropped those lines (the repair call rescued 2 of 40 on
  the gold papers). Now:

  
model wroteread as

  
T2/origin/hatchery-rearedproperty "origin (hatchery-reared)", no invented direction

  
0.3 kg/ha"0.3 kg per ha" (a unit slash is not a field separator)

  
F|11|…|N|exp or effect|N;effect|Na null result (N line)

  
A|5|…, U|7|…an F line with that language (3.4 % of all lines were silently ignored)

  
A/+;B/+ as causeone joint cause "A and B"

  
Full corpus: unparseable lines 2,263 → 223, dropped 1,883 → 128.

  
4b · Expand into nodes and edges

  
    
  
  • Node = entity (T-code → species + NCBITaxon ID), measured_attribute (the quality: "size" for "size of year 1 rosettes"; name keeps the phrase), change qualifier.
    • 
  
  • One edge per effect: predicate, causal_language, original sentence + source span with character offsets and section.
    • 
  
  • Null result → negated: true + no_relationship; the object keeps the tested direction, never "unchanged" (schema rule).
    • 
  
  • Mediator → its own node and two path edges; dose, comparator, season, life stage, scope, evidence type, philosophical accounts filled from keys and the sentence.
    • 
  
  • Hedged sentence (may, might, appears, suggests) labelled "direct" → "uncertain"; paper-defined abbreviations written out in names.
    • 
  
  • Species fan-out: a line listing ≥ 4 species the sentence never names (the model spread "small trees" over the legend) → one "multiple species" node.

  
5 · Guard and merge

  
  • Each edge validated with the nodes it uses against the JSON Schema generated from CAMO; an invalid optional field is dropped, an edge with a broken required field is dropped.
    • 
  
  • Predicate/language repairs (causes + associational → associated_with; correlated_with only with a correlation statistic).
    • 
  
  • The same claim from the same sentence under the same conditions is kept once.
    • 
  
  • Merge: every row of corpus/index.csv gets a source_documents entry with its DOI (also if extraction failed); every edge points to one.

  
6 · Write and validate

  
YAML and JSON written; validated with the JSON Schema and, when installed, linkml-validate -s schema/causalmosaic.yaml -C CausalGraph.
  A failing paper never stops the run; a run with no edges fails loudly instead of writing an empty graph.






  
The evaluator (dev/score/)

  
We built our own scorer to compare a predicted graph with a reference graph, edge by edge, at three levels of strictness.

  
levela predicted edge matches a reference edge when …

  
loosecause and effect entities agree (same NCBITaxon ID, or ≥ 0.5 token overlap of the entity text) and both are null results or both are not

  
standardloose + the effect's measured attribute is similar (Jaccard ≥ 0.5 after lemmas and a synonym table, or the same ID) + directions of change not opposite

  
strictstandard + the same direction of change

  
Matching is one-to-one (best pairs first). Precision = matched / predicted, recall = matched / reference edges, F1 their harmonic mean. Also
  reported: null-result precision/recall, causal-language and predicate accuracy on matched pairs, taxon-ID accuracy, and for every miss
  and extra edge the reason (e.g. "right entities, object attribute differs").

  
How experiments were compared

  

  
Post-processing changes: replay the saved answers of several endpoint runs through old and new code
  (dev/replay.py) — exact, no noise, both stage-1 models.

  
Prompt / preprocessing changes: ≥ 2–3 endpoint runs per variant and model, mean and range; identical runs vary
  (Murphy 0.542–0.583). Murphy, dev3 and reg4 always reported separately (dev/eval8.py); every experiment logged.
